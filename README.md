# AI 求职监控插件

Python标准库＋JSON＋Chrome/Edge Manifest V3＋GitHub Actions。日常更新不调用ChatGPT、Codex或付费模型，不读取招聘平台Cookie，不自动投递或联系招聘方。

## 当前范围

自动读取配置内企业的 **Greenhouse公开Job Board API**（pingcap、mongodb、elastic），获取中国地区涉及AI的原JD，进行规则筛选。读取公开API不等于覆盖中国招聘市场：目前来源有限，可能没有适合初级候选人的结果。配置内企业招聘板名称是来源标识，不代表已核实签约主体。

BOSS、智联、51job、猎聘、牛客提供官方链接与手动JSON导入；**没有启用这些平台的无人值守抓取，也没有完成原来的990项平台检索**。没有验证码绕过、模拟账号批量请求或导出登录态。详见 [来源研究](docs/SOURCES.md)。

## 本机运行

Python 3.11+，无需 pip 包。macOS / Windows 均支持：

```bash
cd ai-job-monitor
python3 -m unittest discover -s tests -v
python3 collector/monitor.py
```

Windows 将 `python3` 替换为 `py -3`。当前 Mac 自带Python已实测；若其他Mac报告证书错误，安装Python发行版的可信证书，或检查系统CA；代码不会关闭TLS验证。

输出：`data/feed.json`（历史岗位＋事件＋汇总）、`data/status.json`（最近尝试，包括失败）、`data/weekly.json`（本周统计）、`extension/seed.json`（安装初始快照）。采集只 GET 官方公开接口。网络超时和5xx最多3次退避重试；401/403/404/429直接记录并停止该来源。

## 安装浏览器插件

1. Chrome手动打开 `chrome://extensions`；Edge打开 `edge://extensions`。
2. 开启开发者模式，点击“加载已解压的扩展程序”。
3. 选择本项目 **extension 文件夹**，不要选择项目根目录。
4. 点击插件图标，可使用“独立窗口”打开完整工作台。
5. 设置与导入中填写云端 `data/feed.json` 的GitHub Raw链接，保存并授予该域名读取权限，再点击同步。

示例地址（仓库部署后才有效）：
`https://raw.githubusercontent.com/qianchengguo/ai-job-monitor/main/data/feed.json`

浏览器工具安全策略不允许自动打开扩展管理页，所以真正加载扩展、系统通知弹窗和Edge加载需用户手动验收；不能把Node单元测试当作这几项已完成的证据。

## 云端部署与每日13:00更新

1. 将这个目录的内容上传到你自己的公开GitHub仓库，默认分支为main。
2. 检查 `.github/workflows/update.yml` 出现在默认分支；定时规则为UTC05:00，即北京时间13:00。
3. 打开仓库 Actions → Update AI jobs → Run workflow，先手动跑一次。
4. 成功运行须看到：测试通过、采集步骤成功、数据提交成功；检查Raw feed的 `generatedAt` 与运行时间一致。
5. 插件保存上面的Raw地址并同步，核对插件“最近可用更新”。
6. 第二天13:00后检查运行由 `schedule` 触发。只有见到实际记录才能确认首次定时运行。

工作流使用GitHub自动提供的GITHUB_TOKEN写入**本仓库**，不需要个人PAT、招聘平台凭据或模型Key。不要在仓库提交个人简历、投递备注、Cookie、邮箱密码或其他秘密。公开仓库的数据与完整JD内容会公开，人工导入时只提交有权公开的招聘资料；个人投递记录只保存在扩展本机。

公开仓库的标准GitHub-hosted runner目前免费（大型runner等不在此范围）；GitHub调度可能延迟，负载高时甚至丢弃任务，默认分支才执行schedule。公开仓库60天无活动可能禁用定时任务。运行和Artifact存储有各自政策，不保证永久免费；本项目7天清理诊断Artifact。官方依据及核实日见来源文档。

插件每小时检查feed，浏览器启动时也同步；电脑和浏览器关闭期间，**云端采集仍可执行，浏览器通知不能即时弹出**。重新打开浏览器后同步。无需电脑全天开机，也不启动Codex。

## 页面和数据

- 总览：完整成功/可用更新时间、来源是否失败、有效线索、高匹配、待核实、本周汇总。
- 最新职位：日期/分数排序、城市/方向/文本筛选、原JD和来源链接、收藏、不感兴趣。
- 每日更新：按北京时间日期显示新发现、内容变化、疑似过期。首次发现不是招聘发布时间。
- 投递记录：未投递、已投递、笔试、面试中、已录用、已拒绝；日期、备注、备份与恢复。
- 手动导入：规范JSON数组，仅浏览器本机保存，统一待核实，不伪造成联网核验。

规则100分：方向25、已毕业2026资格20、本科15、初级经验15、明确无证书要求10、优先城市10、岗位形式5。非优先城市5分，全国可保留。缺少关键证据一律待核实，即使总分较高；缺少说明不表示雇主确认接受。规则无法理解所有自然语言，显示匹配证据和冲突，需人工复核。人工导入不会自动获得高匹配。

明确硕士/英语证书/多年经验/仅在读届次/销售考核/必备CRM或ERP经验冲突排除。当前启用的职务同义识别是正文技术规则，不是只按标题。22个名称保存在采集日志 `roleKeywords` 中，**它们是匹配种子，不冒充对未接入平台执行了22次搜索**。

使用公司＋城市＋规范化标题去重，保留原链接别名；相同岗位在不同城市作为不同记录。更改描述/薪资/招聘日等产生更新事件。源接口成功且连续两次缺失标记疑似过期，不声称已关闭；来源失败不增加缺失计数。历史记录保留在feed，事件保留100天，Git提交提供历史版本；与旧知识库岗位三个月清理规则不自动互相覆盖。旧知识库和用户学习记录均未改动。

## 手动导入格式

```json
[
  {
    "company": "招聘页面的公司全名",
    "title": "招聘页面的真实岗位名称",
    "city": "深圳",
    "salary": "原始薪资或未披露",
    "url": "https://招聘平台/真实岗位地址",
    "description": "你有权保存的完整JD原文",
    "publishedAt": null,
    "employmentType": "全职",
    "direction": "AI实施交付"
  }
]
```

这是字段示意，不是招聘样本。将真实数据保存为JSON后在插件导入。若放入 `data/manual.json`，会被云端规则引擎读入且**公开在仓库**，仍标记未经联网核验；不要放个人信息。删除手工导入只改变本地人工文件，不从未知外部接口自动核验。

## 验收与限制

详见 [验证记录](docs/VERIFICATION.md)。Python规则/持久化、JS同步/通知去重/失败保留测试是自动化证据；Chrome/Edge实际加载、系统通知、首次GitHub schedule须分别记录。仓库文件存在不等于云端跑通。

本版本不提供：全平台自动搜索、企业工商风险保证、自动投递、邮件/飞书通知、跨设备同步私人记录、自动发布到原私有Sites知识库。保留原知识库和本地13点任务，不擅自关闭；确认云端稳定后可再决定是否停用重复的Codex采集任务。
